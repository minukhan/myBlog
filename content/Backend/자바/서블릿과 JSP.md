
### 서블릿이 뭐야??

- 약간 컨트롤러 역할을 해주는 친구.
- 자바로 만든 웹 요청을 받아서 필요한 일을 하고(service), HTTP/JSON 같은 응답을 만들어 돌려주는 역할. 

### 어디서 돌아가?? 

- 서블릿 컨테이너 안에서. 
- Tomcat, Jetty


### 서블릿의 생명주기

1. 클래스 로딩, 인스턴스 생성 (컨테이너가 처음 필요할때 한번 한다.)
2. init : 서블릿당 한번만 호출한다(초기화)
3. service : 매 요청마다 호출하고 처리한다.
4. destory : 애플리케이션 내려갈때 한번 처리한다. 

> 질문 : init -> service -> destory 다음에 뭐가 호출돼?
> 답 : 아무것도 없다. 서블릿은 이미 종료상태임. 


### URL매핑

- 보통 @WebServlet("패턴") 으로 매핑한다. 
- 반드시 "/" 로 시작한다. 
- 호출은 컨텍스트 경로 + 매핑경로
- 패턴 종류
	- 정확 매핑: `"/hello"`
	- 와일드카드: `"/users/*"` → `/users/1`, `/users/list`
	- 루트: `"/"` → 대부분 요청을 잡음(정적리소스/다른 매핑 우선순위에 따라 다름)

### 필터
- **필터(Filter)** 는 **모든(또는 특정 패턴의) 요청 앞·뒤에 끼어드는 관문**

##### 필터 왜씀??
- 만약 공통된 로직이 들어갈경우 하나로 뺴놓고 한번에 공통 로직을 넣을 수 있음.
- 인증/권한 체크, 인코딩 설정, 보안헤더 추가

##### 재정의 해야하는게 뭘까??
- 필터를 쓰려면 Filter를 상속, 구현하고
- 최소한 doFilter를 재정의 해야한다. 
- init(), destory() 는 선택사항임.

### 주요 서블릿/웹 객체들

- HttpServletRequest : 요청 정보
- HttpServletResponse : 응답제어

### JSP 스크립트 요소 & 페이지 이동

- 스크립틀릿 <% ... %> 
	- 자바 코드를 JSP안에 바로 넣는다. 
	- 근데 HTML이랑 자바랑 섞여서 가독성이 떨어짐.
	- 그래서 요즘은 EL/JSTL을 권장한다. 
- 표현식 <%= expr %> 
	- 값 출력하는 코드
	- System.out.print(expr) 랑 같은 코드임. 작은값 출력할때 사용한다. 
- 선언부 <%! ... %>
	- JSP가 서블릿 클래스로 변환될 때, 클래스의 필드/메서드로 들어감.
	- 멀티스레드 환경에서 필드 남발하면 동시성 문제가 생긴다. 

### 주석

- **HTML 주석** `<!-- ... -->`: **브라우저에 전달됨**(소스보기에서 보임).
- **JSP 주석** `<%-- ... --%>`: **서버에서 제거**되어 **브라우저에 안 보임**(비밀 메모용).
- **자바 주석** `//`, `/* */`: 스크립틀릿 안에서만
> <!-- 이건 클라이언트가 볼 수 있음 -->
<%-- 이건 서버에서 사라짐 (추천) --%>

### forward vs redirect 비교

|항목|**forward** (내부 이동)|**redirect** (외부 재요청)|
|---|---|---|
|동작|서버 내부에서 **요청을 다른 리소스로 넘김**|서버가 **브라우저에게 다른 URL로 가라고 지시(302/303/307/308)**|
|주소창|**그대로** (바뀌지 않음)|**바뀜** (새 URL로 이동)|
|요청/응답|**같은 요청**(request 유지)|**새 요청** (request 사라짐)|
|데이터 전달|**request.setAttribute**로 전달 쉬움|쿼리스트링/쿠키/세션/플래시(스프링)로 전달|
|사용 예|화면 렌더링, 에러 페이지 내부 전환|PRG 패턴(중복 제출 방지), 목록으로 돌아가기|
|성능|1번 요청/응답 (서버 내부 이동)|2번 네트워크 왕복(리다이렉트→새 요청)|

- forward 는 3관 영화관에서 그 자리에서 다른 영화 틀어주기
- Redirect는 3관 -> 6관으로 이동하라고 지시. 

### 쿠키와 세션

- 쿠키 
	- 브라우저에 저장. 
	- 키 = 값 + 옵션
	- **Max-Age(초)**: **쿠키가 몇 초 동안 살아있을지(유효기간)** 를 정하는 옵션
		- **>0**: 지정 시간만큼 유지(영속쿠키)
		- **0**: 삭제
		- **-1(기본)**: **세션 쿠키**(브라우저 종료 시 제거 가능)

### 관련 객체/ 메서드
~~~
// 쿠키 쓰기
Cookie c = new Cookie("theme", "dark");
c.setMaxAge(60*60*24); // 1일
c.setHttpOnly(true);
c.setPath("/");
response.addCookie(c);
~~~

### 클라이언트 요청방식

- GET
	- 조회, **URL에 쿼리스트링** 노출, 길이 제한, **캐시**/북마크 가능, **멱등(같은 요청 반복해도 결과 같아야)**
- POST
	- 생성/변경, **바디**에 데이터, 길이제한 실질적으로 널널, 멱등 X(일반적으로)

## 자주 보는 상태코드

- **200** OK
- **302** Found(리다이렉트)
- **400** 잘못된 요청
- **403** 권한 없음(금지)
- **404** 경로 없음
- **405** 메서드 불가(예: GET만 지원)
- **500** 서버 내부 오류

### MVC 패턴 동작 흐름

- 클라이언트가 URL 호출
- Controller가 요청 파라미터를 검증. 그리고 service 호출
- Service 로직이 DAO를 통해서 DB에 접근한다. 
- 그리고 가져온 결과 모델을 request, sesstion에 담아둔다.
- View로 Forward하여 화면에 렌더링 시킨다. 

### 데이터베이스 View ?

- 실제 테이블이 아니라 가상 테이블을 말한다. 
- 쿼리 시점에 원본 테이블을 참조한다. 
##### 사용하는 이유는??

- 보안/캡슐화 : 민감한 컬럼을 숨기고 필요한 컬럼만 노출시킬 수 있음.
- 복잡한 조인, 집계를 한번 정의해놓으면 다음에 안해도 됨.
