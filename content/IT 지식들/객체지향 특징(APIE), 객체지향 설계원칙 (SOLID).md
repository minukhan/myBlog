


### 객체지향 특징 (APIE)

- A(Abstraction) : 추상화
	- 공통된 특징과 기능을 뽑아내서 클래스나 객체로 모델링 하는것. 
- P(Polymorphism) : 다형성
	- 같은 이름의 메서드가 다르게 동작하는것.
	- speak() 메서드가 강아지는 월월, 고양이는 야옹 이런것처럼
- I(Inheritance) : 상속
	- 기존 클래스의 속성과 기능을 물려받아서 새로운 클래스를 만드는 것
- E(Encapsulation) : 캡슐화
	- 데이터와 기능을 하나로 묶고, 외부에서 접근을 제한하는것. 


### 객체지향 설계원칙 (SOLID)

- 객체지향설계의 핵심은 의존성을 잘 관리하기! 

- S(Single Responsibility Principle) : 단일 책임의 원칙 
	- 클래스는 하나만의 책임을 가지고있어야한다. 
	- 클래스가 오직 하나의 목적이나 이유로만 변경되는것을 기억하자!
	- 하나의 클래스가 front, back 둘다 책임이 있으면 안됨. 분리!

- O(Open–Closed Principle) : 개방 폐쇄 원칙
	- 새로운 기능은 기존 코드를 수정하는게 아니라 
	- 새로운 구현체로 확장시킨다. (개방)
	- 기존 코드는 건들이지 않는다. (폐쇄)

- L(Liskov Substitution Principle) : 리스코프 치환원칙
	- 자식클래스는 부모클래스로 대체 가능해야한다. 
	- 그러니까 부모에서 직사각형 가로, 세로 독립적으로 바뀔 수 있도록 해놨는데
	- 자식에서 같이 바꿔야되도록 바꾸면 부모형식을 깨버리는거라 안된다! 이게 리스코프 치환원칙
- I(Interface Segregation Principle) : 인터페이스 분리원칙
	- 너무 많은 기능을 가진 큰 인터페이스보다
	- 작고 목적이 분명한 인터페이스 여러개로 분리해야한다. 
- D(Dependency Inversion Principle) : 의존 역전 원칙 
	- 구체적인 클래스에 의존하면 변경에 취약하다.
	- 인터페이스나, 추상클래스에 의존하면 유연성과 확장성이 향상된다.
