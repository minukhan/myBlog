
### REST가 뭐야?? 

- 자원의 표현을 이용해서 상태를 주고받는 것. 
- 특정 기술 스택이 아니라 “제약”의 집합.(규칙같은것)
- 네트워크 상에서 클라이언트와 서버가 통신하는 방식중 하나임. 
- HTTP 프로토콜을 사용하고 구체적으로 HTTP URL을 활용해서 자원을 명시하고 HTTP METHOD를 통해 CRUD 연산을 적용


### RestFul API 는 뭐지??

- REST 아키텍처 스타일의 제약들을 최대한 충실히 지킨 HTTP 기반 API
- **API(Application Programming Interface)** 란 컴퓨터 프로그램 간 정보를 주고받을 수 있도록 하는 일종의 출입구와 같은 역할을 수행
- API가 REST 기반으로 구현되어 있다면, 이를 REST API라 부른다


### REST의 장단점이 뭘까??

- 서버와 클라이언트 역할을 명확하게 분리해준다. 
- HTTP 프로토콜을 따르는 모든 플랫폼에서 사용할 수 있다. 
- HTTP 메서드로 행위를 표현하기 어려운 경우가 존재해서 요청 한번으로 여러 자원을 가져오는게 어렵다는 단점이 있음. 
- REST의 방식의 경우, 자원의 상태를 JSON 메시지 포맷을 사용한다. 
	- 메시지 소비자가 필요한 것만 골라서 사용하고 나머지는 무시해도 되니까 호환성이 좋음. 
	- 근데 메시지가 길어서 전송 속도가 느리다는 단점이 있다.
