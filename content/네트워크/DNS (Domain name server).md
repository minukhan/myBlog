

### DNS란 무엇인가???

- 도메인 네임 시스템은 사람이 기억하기 쉬운 도메인 이름을 컴퓨터가 통신하는 데 사용하는 IP 주소로 바꿔주는 시스템. 
- OSI 7계층에서 애플리케이션 계층에 속하는 프로토콜이다. 
	- 웹 프라우저나, 이메일 클라이언트같은 다른 애플리케이션 계층 프로세스에 직접적으로 이름 변환 서비스를 제공하기 때문에 애플리케이션 계층. 


### DNS 의 포트번호

- DNS는 포트번호 53을 사용하여 UDP와 TCP 둘다 지원한다. 

- UDP가 주된 이유 
	- 속도가 빠르다는 장점, 낮은 오버헤드떄문. 
	- DNS 쿼리는 보통 단일 요청 패킷과 단일 응답 패킷으로 구성되어있다. 
	- 그렇기 때문에 인터넷에서 끊임없이 발생하는 수많은 DNS 쿼리를 처리하기 위해 효율을 챙김. 

- TCP 가 사용되는 경우는?? 
	- 대용량 응답이 올때!
		- 초기 DNS 명세는 UDP 패킷 크기를 512바이트로 제한함. 
		- 그래서 이 크기를 초과하면 TCP를 통해서 재시도 하도록 유도했다고 함. 
		- 현재 EDNS라는게 도입되어서 더 큰 UDP 패킷을 전송할 수 있으나, 여전히 TCP는 최종적인 대체 수단으로 남아있다!!
	- 보조 DNS 서버가 주 DNS 서버로부터 전체 레코드 데이터베이스를 복제해야할 때, 이는 대규모의 중요한 데이터 전송에 해당된다. 
	- 이때 신뢰성, 완전성, 순서를 보장하기 위해 TCP가 사용된다. 

> DNS 는 기본적으로 UDP를 사용하되 필요할떄 TCP를 사용하는 하이브리드 방식이다!

> 보통 DNS 찾을때, 로컬에 없다면 ROOT 부터 들어가서 아래로 내려가면서 찾아나간다. 

- 재귀적 쿼리??
	- 클라이언트가 자신의 설정된 리졸버에게 `www.example.com`의 IP 주소를 찾아서 최종 답변을 알려줘 라고 요청하는 방식. 
	- 이 요청을 받은 리졸버는 답을 찾거나 실패할 떄까지 다른 서버들에게 쿼리를 보내는 모든 작업을 수행. 
	- 일반적인 사용자 PC가 ISP의 DNS서버에 요청하는 방식. 
- 반복적 쿼리 
	- 클라이언트가 서버에게 "`www.example.com`의 IP를 아니?"라고 물으면 서버는 자신이 아는 최선의 답변을 제공. 
	- 보통은 몰라 TLD 서버에 물어봐봐 라고 참조를 하는 형태임. 
	- 그러면 클라이언트는 참조받은 서버에 다시 쿼리를 보내서 찾는다. 


### UDP 쿼리에서 패킷 손실이되면 어떻게 처리해?? 

- UDP는 비신뢰성 프로토콜임. 
- 그래서 DNS 쿼리나 응답 패킷이 손실되는 것들을 DNS 프로토콜 자체에서 처리하지 않는다. 
- 이 책임은 애플리케이션 (DNS 클라이언트) 에 넘긴다.
- 쿼리를 보낼때, 타이머를 시작하고 응답이 타이머 만료전에 도착하지 않으면 패킷이 손실된 것으로 간주하여 쿼리를 재전송한다. 


### 잘못된 DNS 캐시 항목의 수정. 

- DNS 리졸버와 클라이언트는 응답속도를 높이기 위해서 조회 결과를 캐싱함. 
- 잘못된 정보가 캐싱되면 연결문제가 발생한다.

- TTL (Time to Live) : 
	- 모든 DNS 레코드에는 도메인 관리자가 설정한 TTL 값이 초 단위로 포함되어있음. 
	- 시간이 만료되면 캐시된 항목을 폐기. 반드시 권한있는 서버에 다시 쿼리하여 최신정보 가져옴. 
- 잘못된 레코드를 수정하려면 권한 있는 서버에서 레코드를 올바르게 변경.
	- 그러면 인터넷 전역의 다른 리졸버들이 잘못된 레코드를 수정하고 점진적으로 수정된 정보가 전파됨. 
- 수동 수정 
	- 최종 사용자는 DNS 캐시를 수동으로 비워서 강제로 새로운 조회를 할 수 있음.


> [!note] 참고
> DNS 시스템은 가능한 한 요청 지점과 가까운 지점에서 쿼리에 응답하도록 설계되어있음. 


### DNS 레코드 타입: A, CNAME, AAAA

- A 레코드 
	- “도메인 이름을 **IPv4 주소(예: 93.184.216.34)**로 변환”
	- 가장 기본적인 레코드 타입. 호스트 이름을 IPv4 주소에 직접 매핑한다. 
- AAAA 레코드 
	- “도메인 이름을 **IPv6 주소**로 변환”
	- A 레코드의 IPv6버전.
	- 호스트 이름을 IPv6 주소에 매핑한다. 
- CNAME 레코드
	- 직접 IP 주소를 가지지 않고 **다른 도메인 이름을 참조함**
	- DNS 리졸버는 이 이름이 가리키는 **정식 이름(Canonical Name)** 을 다시 조회해야 함
	- 그러면 왜 사용해?? 

```
example.com → 93.184.216.34
www.example.com → 93.184.216.34
ftp.example.com → 93.184.216.34
api.example.com → 93.184.216.34
```

이 경우 **모든 도메인에 A 레코드를 각각 등록해야** 합니다.  
만약 서버 IP가 변경되면 어떻게 될까요?

→ IP를 변경할 때 **모든 도메인의 A 레코드를 다 수정해함!!   
→ 관리가 번거롭고, 실수 가능성이 큽니다.

CNAME 을 사용하면?? 

```
example.com.     IN A 93.184.216.34
www.example.com. IN CNAME example.com.
ftp.example.com. IN CNAME example.com.
api.example.com. IN CNAME example.com.
```

### hosts 파일은 어떤 역할을 하나???

- hosts 파일은 로컬 운영체제에 존재하는 텍스트 파일을 말함. 
- 호스트 이름과 IP주소간의 정적인 매핑 정보를 담고있다. 
- 도메인 이름을 분석할때, 외부 DNS 서버에 쿼리를 보내기 전에 먼저 hosts 파일을 확인한다. 
- 이떄 DNS 조회보다 더 높은 우선순위를 가지므로 이를 이용해 로컬 테스트 환경을 구축하거나, 특정 사이트로의 접근을 차단하는 용도로 활용할 수 있다고 함.
