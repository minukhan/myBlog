
### 소켓과 포트의 차이가 무엇인가??

- 표준 소켓, 웹 소켓은 모두 네트워크 통신을 위한 연결점 역할. 

- **표준 소켓** = “그냥 선” → 규칙은 네가 정해.
- **웹소켓** = “HTTP 위에서 약속된 규칙” → 그 규칙을 따르면서 실시간 양방향 통신 가능.

> 표준 소켓은 그냥 연결만 하고 규칙따위는 없다. 그래서 어떤 언어로, 어떤 규칙으로 통신할지를 개발자가 자체적으로 만들어야함.
> 
> 그러나 웹 소켓은 기존에 있는 HTTP를 사용함으로써 규칙은 기존에 있는걸 따르고 실시간 양방향 통신이 가능하다!!

### 그러면 표준소켓은 양방향 통신이 안돼??

- TCP 연결을 맺으면 양방향 가능하다. 
- 채팅 프로그램, 온라인게임 등 원래부터 TCP 소켓으로 다 구현 가능했다. 

### 뭐야 그러면 다 가능한데 왜 웹소켓이라는게 나왔을까??

- 브라우져는 보안 떄문에 순수 TCP 소켓을 직접 열 수 없었다. 대신 HTTP만 사용할 수 있었음.
- 그래서 나온게 웹소켓!
- HTTP로 시작해서 규칙도 정리해둔 웹친화적인 TCP통신방법. 

![](https://i.imgur.com/TiXLI2v.png)

> 그냥 단순하게 좀 더 세부적으로 규칙을 정하고, 통신방법을 정해놓은게 웹소켓. (HTTP) 를 사용. 

##### 표준 소켓? 

- TCP/IP 프로토콜 스택을 직접 사용하여
- 네트워크를 통해 데이터를 송 수신 하게끔 한다. 

##### 웹 소켓

- 상위 계층 프로토콜로 웹 브라우저와, 웹 서버간의 실시간 양방향 통신
> 통신을 시작할때 HTTP 프로토콜을 사용한다.  
- 클라이언트는 표준 HTTP포트를 통해 서버에 Upgrade 헤더를 포함한 HTTP 요청을 보낸다. 
- 이떄 서버가 수락하면 기본의 HTTP연결은 웹소켓 프로토콜을 사용하는 영구적인 전이중 연결로 전환된다. 
- 편지로 통신하다가 -> 전화로 바뀌는 느낌으로 이해하면 편하다. 
- **보안이 없는 웹소켓은 HTTP의 문을 쓰고, 보안된 웹소켓은 HTTPS의 문을 쓴다**고 이해하면 돼요.
- 보안이 없는 웹소켓 포트 (ws://) : 80번
- 보안이 있는 웹소켓 포트 (wss://) : 443번


### 그러면 여러 소켓이 있다면 그 소켓의 포트 번호는 모두 다른가??

- 포트는 같다! 라고한다. 그 안에서 구별지어진다고 함.

### 그러면 같은 포트안에서 소켓끼리 어떻게 구분짓는데?? 

- 소켓 구분자(4가지 값으로) 구분한다고 함. 
- 소켓을 식별하는 4가지 요소 
	- **출발지 IP (Client IP)**
	- **출발지 포트 (Client Port)**
	- **목적지 IP (Server IP)**
	- **목적지 포트 (Server Port)**
- 예시
	- 서버: `203.0.113.10:443` (HTTPS 서버)
		- 클라이언트 A: `192.168.0.2:51000 → 203.0.113.10:443`
		- 클라이언트 B: `192.168.0.3:52000 → 203.0.113.10:443`
		- 클라이언트 C: `192.168.0.4:53000 → 203.0.113.10:443`
	- 모두 목적지 서버 포트까지 같다!
	- 근데 출발지 IP, Port가 다 다르니까 각각 다른 소켓 연결로 구분됨. 

### 그러면 이런 IP 다른거는 누가해줘??

- TCP/IP 스택을 가진 운영체제 커널이 다음을 해줍니다:
- 새로운 연결이 들어오면, `(출발지 IP, 출발지 Port, 목적지 IP, 목적지 Port)` 네 가지 값을 조합해서 **소켓 테이블**에 저장.
- 같은 목적지 포트(443)로 여러 연결이 와도, 출발지 IP·Port가 다르면 **다른 엔트리(소켓)**로 구분.


### 사용자의 요청이 무수하게 많아지면 소켓도 무수히 생성되나요?? 

- 이론적으로는 소켓이 무수히 생성된다고 함. 
- 근데 현실에는 메모리 제한이 있다. 
> 그래서 소켓 통신을 관리하는 운영체제가 한 프로세스가 동시에 쓸 수 있는 갯수를 제한시킨다. 

>[!note] 정리
>소켓을 무한시 만들 수 있으나, 메모리의 자원 한계 떄문에 무한히는 못만든다.
>그걸 관리하는게 OS 적절한 갯수로 제한시킨다.
>만약 더 늘리고싶다면 이 한계를 늘리거나, 효율적으로 쓰도록 튜닝해야함.
