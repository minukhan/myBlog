
### 라우터가 뭐야??

- 인터넷은 수많은 네트워크의 집합체.
- 이 거대한 네트워크 교차로에서 교통 정리를 담담하는 핵심 장비가 라우터(Router)
- 라우터는 OSI 7계층중 3계층인 네트워크 계층에서 동작한다. 
- 데이터 패킷이 최종 목적지까지 도달할 수 있도록 최적의 경로를 결정하고, 해당 경로로 패킷을 전달하는 역할

### 라우터의 내부구조 

- 고속 패킷 포워딩을 효율적으로 수행하기 위해서 4가지 핵심 기능이 있다. 
	- 1. 입력 포트 
		- 패킷이 라우터로 들어오는 관문.
		- 입력포트는 여러 계층의 기능을 수행한다. 
			- 물리계층 : 전기적 또는 광학적 신호를 비트(bit) 스트림으로 변환
			- 데이터 링크 계층 : 이더넷 프레임과 같은 2계층 헤더를 제거 후 3계층 IP 패킷을 추출 
			- 네트워크 계층 : IP 주소를 확이낳고 포워딩 테이블을 조회해서 이 패킷을 어디로 보낼지 결정하는 핵심적인 기능. 
	- 2. 스위칭 구조
		- 라우터의 심장
		- 입력포트와 출력포트를 물리적으로 연결하는 역할을 한다. 
		- 입력포트에서 목적지가 결정된 패킷은 이 스위칭 구조를 통해 빠르게 전달.
	- 3. 출력포트
		- 패킷이 라우터를 떠나느 출구.
		- 스위칭 구조로부터 패킷을 수신해서 큐(Queue)에 저장하고 입력포트의 역순으로 동작.
			- 네트워크 계층
				- 출력 링크가 혼잡할 경우를 대비해서 버퍼를 저장하고 전송 순서를 관리. 
				- 기본적인 FIFO 외에도 우선순위 큐잉 같은 고급기술도 사용한다. 
			- 데이터 링크 계층 
				- IP 패킷을 새로운 2계층 프레임으로 다시 캡슐화
			- 물리계층
				- 프레임을 신호로 변환해서 물리적인 매체를 통해 전송. 
	- 4. 라우팅 프로세서
		- 라우터의 뇌.
		- 모든 패킷을 직접 처리하진 않음. 그러나 네트워크의 제어 기능을 총괄한다. 
		- OSPF, BFP 같은 라우팅 프로토콜을 실행해서 다른 라우터와 경로 정보를 교환
		- 이를 바탕으로 라우팅 테이블을 생성한다. 
		- 이후 이 라우팅 테이블을 최적화해서 실제 포워딩에 사용된다. 

> [!note] 참고
> - **라우팅 테이블(RIB)**: “어디로 갈지” **계산**하고 **학습**한 후보 경로들의 집합.
> - **포워딩 테이블(FIB)**: 실제 패킷을 **어디로 보낼지** 최종 결정만 모아둔 **고속 조회용** 테이블.
    

### 패킷 포워딩 단계별 과정 

- 1. 패킷 도착 
	- 패킷이 라우터의 특정 입력 포트로 도착. 
- 2. 헤더 유효성 검사 
	- 라우터는 IP 헤더의 내용이 손상되지 않았는지 확인하기 위해서 헤더 체크섬을 검사함. 
	- 체크섬 값이 일치하지 않으면 패킷에 오류가 발생한걸로 간주하고 폐기. 
	- 위조 방지도 될듯. 
- 3. TTL(Time To Live) 감소 
	- 헤더의 TTL 필드 값을 1 감소시킨다. 
	- 이 값이 0이되면 패킷이 네트워크 내에서 무한히 순환하는 것을 방지하기 위해서 패킷 폐기. 
	- 이걸로 무한 루프를 방지하는 필수적인 메커니즘이라고 함.  
- 4. 포워딩 테이블 조회. 
	- 패킷의 목적지 IP 주소를 기반으로 포워딩 테이블을 조회.  
	- 패킷을 전달할 최적의 출력 포트를 결정. 
- 5. 스위칭 
	- 결정된 출력 포트로 패킷을 스위칭 구조를 통해 전달함. 
- 6. 큐잉 
	- 출력 포트가 이미 다른 패킷을 전송중이라 바쁘면, 도착한 패킷은 잠시 버퍼(큐)에서 대기함. 
- 7. 헤더 재작성 
	- 패킷을 다음 홉으로 보내기 위해서 2계층 프레임 헤더를 만듬. 
	- LAN 에서 사용하는 이더넷 프로토콜과 WAN 구간에서 사용하는 프로토콜이 다를경우 
	- 라우터는 이 둘을 변환하는 역할을 한다. 
- 8. 패킷 출발 
	- 최종적으로 패킷이 출력 포트를 통해서 다음 목적지로 전송됨. 

> 이 전체 과정은 패킷이 최종 목적지에 도달할 떄까지 경로상에 있는 모든 라우터에서 반복된다.
> 이를 홉-바이-홉 라우팅 이라고 한다.

### 라우팅과 포워딩의 차이가 뭘까?? 

- 네트워크에서 모두 패킷을 목적지까지 전달하는 과정에서 핵심 기능. 
- 이 둘의 관계는 여행 계획과, 실제 운전에 비유할 수 있다. 

- 라우팅 
	- 여행을 떠나기 전에 지도를 펼쳐놓고 출발지에서 목적지까지 전체 경로를 계획하는 과정.
	- 네트워크 전체의 구조를 고려해서 최적의 경로를 결정.
- 포워딩
	- 계획된 경로를 따라 운전하면서 특정 교차로에 도달했을 때, 다음 어느길로 가야할지 순간적으로 판단하는게 포워딩.
	- 라우터에 도착한 개별 패킷을 다음 목적지로 즉시 전달하는 전술적인 동작. 


### 라우팅 알고리즘에 대해서?? 

- 어떤 길로 가는게 빠를지 계산하는 규칙. 프로토콜.
- 최적의 경로는 비용이 낮은 경로를 의미.
	- 홉의 수, 링크의 대역폭, 지연시간 등으로 결정.

- 라우팅 방식은 관리자가 직접 경로를 설정하는 정적 라우팅
- 라우터들이 서로 정보를 교환하여 동적으로 경로를 결정하는 동적 라우팅으로 나눔.
- 현대 네트워크는 대부분 동적 라우팅 알고리즘을 사용함. 
- 크게 3가지 라우팅 방법이 있다.

###### 라우터들 각각 전체 경로를 알고있나??
- No 각각의 라우터들은 다음 이동할 경로만 저장하고있다. 



##### 거리벡터 라우팅

- 각 라우터는 직접 연결된 이웃 라우터까지의 거리 정보만 알고있음. 
- 그리고 내가 갈 수 있는 라우터들의 정보(거리와, 방향) 등을 이웃에게 공유하여 재료로 쓸 수 있게끔 공유한다. 
- 그렇게 점차 퍼져나가면서 모든 라우터가 일관된 경로 정보를 갖게 된다.

> [!important] 주의!!
> 내가 헷갈렸던건데 라우터는 다음 홉(이동할 경로), 이동하는데 드는 비용만 저장한다.
> 
> 근데 거리벡터에서 퍼트린다는데 이게 뭘 퍼트리는거야?? 
> A 에서 B, C, D 를 갈 수있고 각각의 가중치 정보들을 퍼트린다. 
> 여기서 포인트는 퍼트리고 받은 라우터는 저장하는게 아니라 받은걸 가지고 계산을 바로 해버림. 
> 이웃에게서 받은 '전파된 내용(거리 벡터)'은 저장용이 아니라, '어디로 가야 할지 결정하기 위한 계산 재료'로 사용

- **기반 알고리즘**: 벨만-포드(Bellman-Ford) 알고리즘.  
- **대표 프로토콜**: RIP (Routing Information Protocol).
- **장점**: 구현이 비교적 간단합니다.  
- **단점**: 
	- 네트워크 변화에 대한 정보 전파가 느림, 라우팅 루프가 발생
	- 결정적으로 무한 계수 문제가 발생한다. 
		- 특정 링크가 끊어졌을 때 발생.
		- 전파가 늦어서 다리가 끊어졌는데 갈 수 있다고 판단하는 문제를 말함. 

##### 링크상태 라우팅

- 모두가 전체 지도를 가지는 방식임. 
- 각 라우터는 자신과 연겨로딘 링크의 상태를 파악. 
- 이 정보를 LSP(Link-State Packet) 라는 패킷에 담아서 모든 라우터들에게 전파.
- 이렇게 수집한 LSFP를 모아서 네트워크 전체의 동일한 토폴로지 맵을 구축. 

- 기반 알고리즘 : 다익스트라(Dijkstra) 알고리즘
- **대표 프로토콜**: OSPF (Open Shortest Path First)
- 장점 :
	- 네트워크 변화에 빠르게 대응
	- 더 정교한 경로 결정이 가능
- 단점 :
	- 구현이 복잡하고 
	- 전체 정보를 저장하기 위한 메모리와 알고리즘을 수행할 CPU 자원을 더 많이 소모.

##### 경로 백터 라우팅

- 거리 벡터 방식 변형
- 서로 다른 조직의 네트워크간의 라우팅에 사용됨. 
- 단순하게 목적지까지의 거리만 광고하는게 아니라, 목적지에 도달하기 위해서 거쳐가야 하는 자율 시스템들의 전체 경로 정보를 알림. 
- 대표 프로토콜 : BGP(Border Gateway Protocol)



### 포워딩 테이블의 구조에 대해 설명

- 포워딩 테이블은 라우터가 패킷을 전달할때 사용하는 데이터 구조. 
- 방대한 라우팅 테이블에서 필수 정보만을 추출해서 최적화한 매우 빠른 요약본 

##### 구성 요소

- 목적지 네트워크 주소 
	- 패킷이 향하는 목적지 네트워크의 주소 
- 프리픽스 길이/ 넷마스크 
	- 목적지 네트워크 주소의 범위를 정의 
- 다음 홉 
	- 가야할 다음 라우터의 IP주소 
- 출력 인터페이스 
	- 다음 홉으로 패킷을 내보내는 물리적인 포트
