
### 3-Way Handshake 란??

- TCP 프로토콜을 사용해서 연결을 할때 거쳐야하는 과정 

- TCP는 신뢰성 있는 양방향 통신을 보장되기 위해 3-Way HandShake를 진행한다. 
- 이 과정은 양측이 통신할 준비가 되었음을 확인!
- 데이터 전송에 필요한 초기 매개변수를 동기화

### 어떤 과정으로 수행되나?? 

![](https://velog.velcdn.com/images%2Faverycode%2Fpost%2F22a2bab1-c8dd-4559-88b2-62d03cbff927%2F%E1%84%80%E1%85%B5%E1%84%89%E1%85%AE%E1%86%AF%E1%84%86%E1%85%A7%E1%86%AB%E1%84%8C%E1%85%A5%E1%86%B8-5.jpg)

- 1단계(SYN) : 
	- 연결을 시작하려는 클라이언트는 서버에 TCP 세그먼트를 전송. 
		>이 패킷은 서버의 포트가 열려있는지, 연결을 수락할 의사가 있는지 물어본다.
	
	- 세그먼트 헤더에는 SYN 제어 플러그가 1로 설정. 

- 2단계 (SYN + ACK) : 
	- 서버는 클라이언트의 SYN 패킷을 수신하면 연결 요청을 수락!!
	- 그 표시로 응답 세그먼트를 전송한다. (이 헤더에는 SYN + ACK) 가 모두 1로 설정. 

- 3단계 (ACK) : 
	- 클라이언트는 서버로부터 SYN - ACK 패킷을 수신한 후에 ACK 세그먼트를 서버에 전송.
	- 이 세그먼트의 ACK 플래그는 1로 설정됨.


> [!note] 참고
> 
> SYN 과 ACK는 원래부터 모든 TCP 세그먼트 헤더에 포함된 제어플래그 필드의 일부이다.
> 항상 보내는 거에는 포함되어있음. 그저 0으로 보내느냐, 1로보내느냐 차이
>  


### 2단계로 하면 되는거 아니야?? 왜 3단계까지가??

- **지연된 패킷 문제 방지**
    - 오래된 SYN 패킷이 늦게 도착하면, 서버가 새로운 연결로 착각할 수 있음.
    - 3번째 ACK가 있어야 클라이언트가 “이건 진짜 현재 연결임”을 확인시켜줌.  
        → **‘Half-Open’(좀비) 연결 방지**
        
- **양방향 순서 번호 동기화**
    - TCP는 양방향 통신이라 양쪽이 각각의 초기 순서 번호(ISN)를 서로 확인해야 함.
    - 2단계만 하면 서버 ISN에 대한 클라이언트의 확인이 없음.  
        → 3번째 ACK로 **서로의 순서 번호 동기화 완료**
        
- **상호 연결 합의(Mutual Agreement)**
    - 클라이언트는 2단계 후 서버가 응답했음을 알지만,  
        서버는 클라이언트가 자신의 SYN-ACK를 받았는지 모름.
    - 3번째 ACK가 이를 확인시켜줌.  
        → **양쪽 모두 “연결 완료” 상태를 확실히 인식**

> 그냥 서버가 SYN + ACK를 보냈는데 잘 갔는지 모르니까 3까지 가는거라고 이해.


### 신뢰성을 챙기기 위한 3 - Way HandShake 악용한 보안 위협!

- SYN Flooding
	- 대표적인 3-way Handshake의 취약점을 악용하는 서비스 거부 공격(DoS) 
	- 출발지 IP 주소를 위조해서 대량의 SYN 패킷을 서버로 전송함.
	- 이떄 서버는 SYN + ACK로 응답하는데 자원을 할당함. 
	- 그러나 출발지가 위조되었기 때문에 아무것도 없거나 이상한곳으로 응답이 감. 그래서 마지막 단계 ACK 응답이 오지 않는다. 
	> 이때 서버의 연결 대기 큐가 꽉 차게되는데 타임아웃이 될 떄까지 자원을 점유한다. 
	   그렇게 모두 자원이 고갈된 서버는 정상적인 연결 요청을 수락할 수 없음.


##### 이 문제를 해결하기 위한 방안

- SYN 쿠키 
	- 서버가 SYN 수신 할 때, 바로 자원을 할당하는게 아니라 ACK까지 받았을때 자원을 할당해서 SYN Flooding 방지. 
- 백로그 큐 증가
	- 운영체제의 SYN 큐 크기를 늘려서 더 많은 연결을 수용할 수 있도록 하는것. 공격이 커지면 여전히 문제. 일시적인 해결방법임. 
- SYN-RECEIVED 타이머 단축
	- 타임아웃을 빠르게 되도록 만들어서 자원을 빠르게 회수.
