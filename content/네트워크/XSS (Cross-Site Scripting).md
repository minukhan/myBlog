
### XSS가 뭐야?? 

- 보안 취약점
- 공격자가 악의적인 스크립트를 신뢰할 수 있는 웹사이트에 삽입
	-> 해당 스크립트가 다른 사용자의 브라우저에서 실행되도록 만드는 공격기법
- 공격이 성공하면 여러 악성 행위 가능.
	- 사용자의 세션 쿠키를 탈취, 계정 도용. 
	- 키보드 입력을 가로채서 개인정보를 뺴냄.
	- 가짜 로그인 페이지를 보여주는 피싱 공격 등.


### XSS 공격은 3가지 유형으로 나뉜다. 

- 저장형 XSS (Stored XSS)
	- 공격자가 삽입한 악성 스크립트가 DB나 파일 시스템에 영구적으로 저장되는 위험한 유형
	- 한번의 공격으로 다수에게 큰 피해를 줄 수 있음. 
- 반사형 XSS (Reflected XSS)
	- 악성 스크립트가 서버에 저장되는게 아니라, 사용자의 요청에 포함되어 서버에 갔다가 응답에 그대로 포함되어 사용자에게 전달. 
	- 링크를 클릭하면 악성 요청을 빠르게 반사해서 다시 사용자에게 심어버리는 것. 
- DOM 기반 XSS(DOM-based XSS)
	- 서버와는 무관하게 브라우저의 클라이언트 측 스크립트가 DOM을 조작하는 과정에서 발생.
	- 악성 스크립트가 포함된 URL을 클릭하면 브라우저가 페이지를 생성할떄 DOM에 악성 스크립트가 삽입됨. 
	- 서버는 탐지하기 매우 힘듬. 


## [[CSRF (Cross-Site Request Forgery)]]랑 XSS는 어떤 차이가 있나요?


- 모두 웹 브라우저를 통해서 사용자 공격하는 기법
- 핵심차이 : 
	- CSRF는 공격자 페이지가 사용자 브라우저를 이용해서 다른사이트로 요청을 보내게 하는것. 
	- 그래서 스크립트 주입하지 않음. 근데 XSS는 사이트 안 스크립트에 주입되어서 그 스크립트가 마음대로 요청하고 정보를 탈취한다. 


### XSS 는 Frontend 에서만 막을 수 있나??

- 모두의 책임이지만, 가장 중요한 방어는 백엔드에서 이루어져야함. 

##### backend에서 

- 입력 검증 & 정규화 
	- 형식을 확인하고 예상 밖의 값은 거절
- 출력 인코딩
	- 화면에 뿌릴 떄, 컨텍스트별 인코딩이 필수다. 
- CSP 적용
	- `Content-Security-Policy`로 **스크립트 출처 제한**
- 쿠키보안
	- 세션 쿠키에 `HttpOnly; Secure; SameSite=Lax/Strict` 설정.

##### Frontend에서

- **프레임워크 기본 방어 유지시키기
	- **: React/Vue/Angular의 자동 이스케이프 **그대로 사용**. `dangerouslySetInnerHTML`/`v-html`/`[innerHTML]`는 지양.
- **DOM 조작 안전 API 사용하기 
	- **: `.innerHTML`/`document.write` 대신  `textContent`, `createElement`, setAttribute` 사용.
- 라이브러리 사용시 
	- 리치 텍스트/마크다운은 **검증된 Sanitizer**(화이트리스트 기반) 필수.
