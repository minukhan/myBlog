

### DB Join 이 뭔지 설명하고 종류에 대해서 설명해주세요 

- **Inner Join (내부 조인):** 두 테이블 간의 교집합을 구하는 연산이다. 
- **Outer Join (외부 조인):** 매칭되지 않는 데이터의 보존 여부에 따라 Left, Right, Full Outer Join으로 나뉜다.
    - **Left Outer Join:** 왼쪽(선행) 테이블의 모든 튜플을 보존
    - **Right Outer Join:** 오른쪽 테이블의 데이터를 보존
    - **Full Outer Join:** 양쪽 테이블의 모든 데이터를 보존
- **Cross Join (교차 조인):** 조인 조건 없이 두 테이블의 모든 가능한 조합을 생성한다. 
- **Semi-Join (세미 조인):** 주로 `EXISTS`나 `IN` 서브쿼리에서 사용
- **Anti-Join (안티 조인):** `NOT EXISTS`나 `NOT IN`에서 사용


### 조인 내부 구현 알고리즘

- 논리적 조인이 무엇을 가져올지 정의 한다면 어떻게 가져올지 결정한다. 
- DB 옵티마이저는 테이블의 통계 정보(행 수, 블록 수, 분포도), 인덱스 유무, 가용 메모리 등을 고려하여 Nested Loop, Sort Merge, Hash Join 중 가장 비용 효율적인 알고리즘을 선택한다.

- Nested Loop Join (NLJ) — “이중 for문 조인”
	- 외부 테이블에서 한 줄 읽고
	- 내부 테이블을 스캔하면서 매칭되는 행 찾기 (**for(i) { for(j) }** 구조)

- Sort Merge Join (SMJ) — “정렬한 뒤 병합”
	- 양쪽 테이블을 조인 키 기준으로 정렬.
	- 두 정렬된 리스트를 포인터 이동하면서 병합한다. 
	- 대용량 처리에 유리, 범위 조인도 가능, 결과가 정렬된 상태로 나오게 된다. 
	- 그러나 정렬 떄문에 메모리 소모가 크고 부족함녀 다시 디스크로 내려가서 느려짐. 

- Hash Join (HJ) — “해시 테이블 만들어서 O(R+S)”
	- 작은 테이블을 기준으로 **해시 테이블 생성 (Build)**
	- 큰 테이블을 스캔하면서 해시 테이블에서 매칭되는 버킷을 조회한다. 
	- 대용량 조인이 최고이며 인덱스가 필요하지 않다. 메모리 부족문제가 발생할 수 있다. 


### 옵티마이저의 실행계획 확인 및 분석방법

- MySQL, PostgreSQL
	- EXPLAIN 키워드를 쿼리 앞에 붙여서 사용한다. 
	- 최신버전에서는 EXPLAIN ANALYZE를 사용해서 실제 쿼리를 실행하고 각 단계별 소요 시간과 처리된 행 수를 측정할 수 있다. 
	- EXPLAIN ANALYZE 는 예측값이 아니라 실측값을 제공하므로 성능 디버깅에 매우 좋다. 
- Oracle 
	- `EXPLAIN PLAN FOR <SQL>; SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);` 명령

### 3중조인을 할 경우 성능 분석 

- 두개의 테이블을 조인하는 것은 비교적 단순하지만, 3개 이상의 테이블을 조인하는 경우는 기하급수적으로 복잡해진다. 
- 데이터베이스는 한번에 3개의 테이블을 동시에 조인하지 않는다. 
- 대신 2개를 먼저 조인하고 나머지를 조인하는 순차적 방식을 사용함. 
- 조인 순서에 따라서 성능이 달라지는데, 중간 결과 집합의 크기를 최소화 하는 순서를 찾는게 더 좋다고 한다. 0 -> 100 -> 20 이것보다 0 -> 50 -> 100 뭐 이런게 더 좋다고 함. 
- 테이블 개수가 적을때 옵티마이저는 모든 가능한 순서의 비용을 계산하고 선택한다고 함. 그러나 테이블 갯수가 많다면 휴리스틱 알고리즘을 사용한다고 함.

> 휴리스틱 알고리즘? : 완벽한 최적해보다는 제한된 시간, 자원안에서 충분히 좋은 자원을 찾는 방법을 말함. 

- 방식은 크게 2가지가 있다. 
	- 구체화 
		- 첫번쨰 조인 결과(A+B)의 결과를 임시 테이블이나 디스크에 물리적으로 기록한 후, 이를 다시 읽어 세번째 테이블과 조인한다. 
		- 이를 다시 읽어서 세 번쨰 테이블과 조인한다. 
		- 메모리 부족시 발생하며 I/O 비용이 매우 크다. 
		- 물리 메모리에서 다 못돌리니까 하드디스크를 이용해서 저장했다가 처리한다 이말

	- 파이프라이닝 
		- 첫번째 조인의 결과가 생성되는 즉시 스트림 형태로 다음 조인 연산자의 입력으로 전달된다.
